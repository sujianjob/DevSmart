# AI 原生需求工作流概念

## 核心观点

AI 原生需求工作流不是把模板自动填满，而是让系统主动识别信息缺口、提出澄清问题、补齐边界和验收口径，最后产出可以进入评审的需求包。

## 工作流

```text
自然语言需求 -> 模糊度判断 -> 澄清问题 -> 用户补充 -> 结构化 PRD -> AC -> 待确认项 -> 评审输出
```

## 为什么不是通用聊天

通用聊天可以生成文本，但难以稳定执行以下步骤：

- 先判断需求是否足够清晰。
- 优先追问阻塞性问题。
- 统一 PRD 和 AC 结构。
- 对异常、边界、非目标进行补漏。
- 保留假设和待确认项，方便评审。

## 设计原则

- 先澄清，再生成。
- 不确定的内容必须标记为假设或待确认。
- AC 必须可测试、可判断。
- 评审版输出必须保留修改记录和关键风险。

## 第一阶段验证

第一阶段只验证：

1. 澄清问题是否能命中真实信息缺口。
2. PRD 初稿是否能进入评审。
3. AC 是否足够可测试。
4. 待确认项是否能减少评审遗漏。
