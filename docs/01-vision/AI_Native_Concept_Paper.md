# AI 原生研发概念说明

## 核心观点

AI 原生研发不是把 AI 插进旧流程，而是让流程本身围绕 AI 可读、可执行、可审计的结构化产物重组。

DevSmart 的切入点是：

```text
自然语言需求 -> 结构化 PRD -> 任务上下文包 -> 外部执行 -> 质量建议 -> 审计轨迹
```

## 为什么不是 IDE

IDE 和 Coding Agent 负责“怎么写代码”。DevSmart 负责“什么任务值得做、上下文是否充分、过程是否经过审批、结果是否可追踪”。

## AI 原生要求

- 需求必须结构化。
- 任务必须可拆解。
- 上下文必须可打包。
- 审批必须可中断。
- 执行必须可回收。
- 过程必须可审计。

## POC 判断标准

POC 不证明“AI 能全自动开发”，只证明：

1. PRD 初稿是否可采纳。
2. 任务拆解是否可评审。
3. 上下文包是否能减少沟通。
4. 流程记录是否能支持复盘。

详细执行范围见 [30 天 POC 详细目标](../03-architecture/Thirty_Day_POC_Plan.md)。
