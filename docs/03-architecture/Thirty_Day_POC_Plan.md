# 30 天 POC 详细目标

## 目标

30 天内交付可演示、可内测的最小闭环系统：

```text
需求输入 -> 模糊度判断 -> 澄清问题 -> 用户补充 -> PRD 生成 -> AC 生成 -> 待确认项 -> 评审输出
```

## 第 1 周：骨架与数据模型

交付：

- 需求包数据模型。
- 状态机。
- 需求输入页。
- 基础列表和详情页。

验收：

- 能创建需求包。
- 能看到状态变化。
- 能记录评审和生成事件。

## 第 2 周：澄清问题

交付：

- 需求分析能力。
- 模糊度判断。
- 信息缺口列表。
- 澄清问题生成。

验收：

- 清晰需求可以直接进入 PRD 生成。
- 模糊需求能生成 3-5 个有效问题。
- 用户回答能被合并到需求包。

## 第 3 周：PRD 与 AC

交付：

- PRD 生成。
- AC 生成。
- PRD 编辑页。
- AC 清单页。

验收：

- PRD 包含目标、用户故事、范围、主流程、边界和非目标。
- AC 覆盖主流程、异常流程和边界场景。
- AI 假设被明确标记。

## 第 4 周：补漏与评审输出

交付：

- 待确认项清单。
- 风险和边界摘要。
- 评审输出页。
- 5 个演示样例。

验收：

- 能完整演示从需求到 PRD/AC。
- 能批准、驳回或要求修改。
- 能导出评审版需求包。

## 不包含

- 代码生成。
- 技术方案设计。
- API 或数据库设计。
- 研发任务拆解。
- 外部项目管理工具同步。
- 企业级权限。

## 指标

| 指标 | 目标 |
|:---|:---|
| PRD 初稿可采纳率 | ≥ 60% |
| AC 可测试性评分 | ≥ 4/5 |
| 澄清问题有效率 | ≥ 70% |
| 从需求到评审版需求包耗时 | ≤ 10 分钟 |
| 内测用户愿意继续使用比例 | ≥ 60% |
