# 实现与配置边界

## POC 实施边界

| 层级 | 用途 |
|:---|:---|
| 前端 | 需求工作台、澄清问答、PRD/AC 编辑与评审 |
| 后端 | 保存需求包、状态、评审记录和生成结果 |
| 工作流 | 管理需求包状态，不承载工程执行流程 |
| 模型路由 | 需求分析、澄清问题、PRD、AC 和补漏 |
| 存储 | 原始需求、澄清记录、PRD、AC、待确认项、评审记录 |

## 模型路由

不在业务逻辑中硬编码具体模型。

| 路由 | 用途 |
|:---|:---|
| `analysis-model` | 需求理解、模糊度判断、信息缺口识别 |
| `prd-model` | PRD 生成和改写 |
| `ac-model` | AC 生成和可测试性检查 |
| `low-cost-model` | 摘要、格式化、标签分类 |

## 暂不引入

- 代码仓库读取。
- 研发任务拆解。
- API 设计自动生成。
- 工程执行工具调度。
- 自动 CI/CD。
- 企业级权限。

## 版本原则

- 实施时使用最新稳定版。
- 在依赖文件中锁定具体版本。
- 记录验证日期。
- 产品文档只描述原则，不维护容易过时的小版本号。
