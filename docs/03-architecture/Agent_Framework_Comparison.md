# 需求生成能力选型

## 结论

POC 阶段不建设多 Agent 系统。只保留按阶段调用模型的需求工作流：需求分析、澄清问题、PRD 生成、AC 生成和补漏检查。

## 理由

| 要求 | 处理方式 |
|:---|:---|
| 流程可控 | 用显式状态流转管理 |
| 输出稳定 | 用固定模板和结构化输出约束 |
| 人工评审 | 每个 PRD/AC 都可编辑、可驳回 |
| 低复杂度 | 不引入多 Agent 拓扑 |

## 暂不采用多 Agent 的原因

| 方向 | 暂不采用原因 |
|:---|:---|
| 多 Agent 协作 | 当前任务不需要复杂角色协同 |
| 工程执行 Agent | 超出产品边界 |
| 代码仓库分析 Agent | 当前不做技术上下文 |
| 测试执行能力 | 改为 AC 可测试性检查，不做测试执行 |

## 使用边界

- 模型只负责生成和改写需求内容。
- 状态流转由应用层管理。
- 所有假设和待确认项必须显式返回。
