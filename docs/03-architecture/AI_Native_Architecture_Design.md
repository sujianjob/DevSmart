# 产品工作流设计

## 目标

支撑从模糊需求到 PRD/AC 需求包的最小闭环，并为后续模板库、版本对比和评审协作保留扩展点。

## 分层

```text
需求工作台
  -> 工作流服务
  -> 内容生成能力
  -> 数据与评审记录
```

## 核心组件

| 组件 | 职责 |
|:---|:---|
| Requirement Workspace | 需求输入、澄清问答、PRD/AC 编辑和评审 |
| Workflow Service | 控制需求包状态流转 |
| Requirement Analyzer | 识别已知信息、模糊度和信息缺口 |
| PRD Generator | 生成结构化 PRD |
| AC Generator | 生成可测试验收标准 |
| Gap Checker | 检查边界、异常、非目标和待确认项 |
| Review Record | 保存评审意见和修改记录 |

## 工作流边界

- 只处理需求表达、PRD、AC、边界和评审材料。
- 不生成代码。
- 不设计技术方案。
- 不设计 API、数据库或系统架构。
- 不拆解研发执行任务。

## 后续扩展原则

- 模板库优先于复杂平台能力。
- 版本对比优先于多人流程编排。
- 需求质量评分优先于工程执行追踪。
