# DevSmart 战略分析摘要

> 本文件保留战略结论，详细产品范围以 [PRD](../PRD.md) 为准。

## 战略定位

DevSmart 不进入代码补全和 IDE 红海，而是定位为 AI 研发流程控制平面。它连接 PM、Tech Lead、研发、QA 与外部 Coding Agent，解决需求到执行之间的上下文断层。

## 目标客户

优先面向 20-200 人的研发团队或业务线，而不是一开始进入大型集团级治理场景。原因是 POC 阶段需要快速验证采纳率，过早进入企业级集成会稀释核心验证。

## 差异化

| 竞品类型 | 主要能力 | DevSmart 差异 |
|:---|:---|:---|
| IDE / Copilot | 代码生成 | 上游任务和上下文控制 |
| 项目管理工具 | 任务记录 | AI 生成 PRD、任务和上下文包 |
| 自研 Agent | 单点自动化 | 跨角色流程编排和审计 |

## 近期战略

1. 先验证 PRD 与任务上下文的采纳率。
2. 再接入 GitHub、Jira/Linear 和外部 Coding Agent。
3. 最后扩展企业治理、私有化部署和审计合规。

## 主要风险

| 风险 | 应对 |
|:---|:---|
| 平台范围过大 | 以 30 天 POC 最小闭环收敛 |
| AI 产物不可用 | 以采纳率作为核心指标 |
| 用户不信任自动化 | 坚持 Human-in-the-Loop |
| 工具链变化快 | 使用模型路由和 Adapter 抽象 |

## 当前结论

继续推进，但必须避免“大而全”平台叙事。第一阶段只证明从需求到任务上下文包的闭环价值。
