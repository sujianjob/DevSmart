# DevSmart 战略分析摘要

> 本文件保留战略结论，详细产品范围以 [PRD](../PRD.md) 为准。

## 战略定位

DevSmart 不进入代码生成、项目管理或工程执行工具赛道，而是定位为 AI 需求澄清与 PRD/AC 生成工作流。它解决的是需求进入评审前的质量问题：目标不清、边界缺失、验收标准不可测试、待确认项分散。

## 目标客户

优先面向需要频繁产出 PRD 的产品团队、创业团队和业务产品线，而不是一开始进入大型集团级需求治理场景。原因是 POC 阶段需要快速验证 PRD/AC 产物是否被真实评审采纳。

## 差异化

| 竞品类型 | 主要能力 | DevSmart 差异 |
|:---|:---|:---|
| 通用 AI 对话 | 文本生成 | 固定澄清、补漏、AC 和评审输出流程 |
| 文档工具 AI | 文档润色和补写 | 面向产品需求结构和评审质量 |
| 项目管理工具 | 任务记录和协作 | 进入任务前先提高需求质量 |
| PRD 模板库 | 静态结构 | 动态识别缺口并追问 |

## 近期战略

1. 先验证 PRD 与 AC 的评审采纳率。
2. 再支持团队模板、行业场景和版本对比。
3. 最后扩展需求质量评分、历史需求复用和轻量评审协作。

## 主要风险

| 风险 | 应对 |
|:---|:---|
| 输出像普通 AI 文案 | 强化澄清、补漏、AC 和待确认项 |
| PRD 太长不可用 | 提供精简版、评审版和详细版三种输出 |
| 用户不愿回答澄清问题 | 控制问题数量，优先问阻塞性问题 |
| 范围重新变大 | 坚持不做代码、技术方案和工程执行 |

## 当前结论

继续推进，但必须避免“大而全”平台叙事。第一阶段只证明从模糊需求到 PRD/AC 需求包的闭环价值。
