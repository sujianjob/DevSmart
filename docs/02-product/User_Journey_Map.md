# 用户旅程

## 核心旅程：从模糊需求到评审版需求包

| 阶段 | 用户动作 | 系统动作 | 产物 |
|:---|:---|:---|:---|
| 输入需求 | 输入自然语言需求 | 保存原始需求并提取已知信息 | 原始需求记录 |
| 判断清晰度 | 查看系统判断 | 识别信息缺口 | 模糊度结果 |
| 澄清 | 回答关键问题 | 合并用户补充 | 澄清记录 |
| 生成 PRD | 查看和编辑 PRD | 生成结构化文档 | PRD 初稿 |
| 生成 AC | 查看验收标准 | 生成可测试 AC | AC 清单 |
| 自动补漏 | 查看缺口和风险 | 检查边界、异常和非目标 | 待确认项 |
| 评审 | 批准、驳回或要求修改 | 记录评审意见 | 评审版需求包 |

## 关键体验目标

- 用户不从空白文档开始。
- 系统先追问关键缺口，而不是直接堆文字。
- PRD 和 AC 可以被快速评审。
- 待确认项清晰暴露，不混在正文里。
