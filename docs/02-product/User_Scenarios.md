# 用户场景 (User Scenarios)

## 场景 1：日常需求开发

### 场景描述
产品经理小林需要将一个新功能需求传达给研发团队。

### 传统流程 (Before)
1. 小林花费 2 天撰写 PRD 文档
2. 组织需求评审会议（1-2 小时）
3. 研发提出问题，小林补充文档
4. 重复 2-3 轮直到达成共识
5. 研发开始开发

**问题**：耗时长、信息损耗大、反复沟通

### DevSmart 流程 (After)
1. 小林在 DevSmart 中描述需求意图
2. **PM Agent** 自动生成结构化 PRD 初稿
3. AI 主动追问模糊点，小林补充
4. AI 自动检查逻辑一致性，标记潜在问题
5. 研发在系统中直接查看可执行的任务列表

**改进**：效率提升、质量更高、可追溯

## 场景 2：紧急 Bug 修复

### 场景描述
线上出现紧急 Bug，需要快速定位和修复。

### 传统流程 (Before)
1. 运维收到告警
2. 手动排查日志，耗时 30+ 分钟
3. 拉群定位问题涉及的研发
4. 研发本地复现、修复、提交
5. 手动验证、部署

**问题**：响应慢、依赖个人经验

### DevSmart 流程 (After)
1. 系统自动接收告警
2. **Ops Agent** 分析日志，给出根因假设
3. 自动关联到最近的代码变更
4. 生成修复任务上下文，推送给相关研发
5. 验证完成后自动更新任务状态

**改进**：MTTD 降低 90%、信息自动关联

## 场景 3：代码审查

### 场景描述
研发小王提交了一个 PR，需要进行代码审查。

### 传统流程 (Before)
1. 小王创建 PR，@审查者
2. 审查者人工逐行阅读代码
3. 提出修改意见
4. 多轮修改和确认

**问题**：审查者负担重、容易遗漏

### DevSmart 流程 (After)
1. PR 创建后，**QA Agent** 自动进行预审查
2. 检查：代码规范、潜在 Bug 模式、测试覆盖
3. 生成审查报告，标记需要人工关注的点
4. 审查者聚焦高优先级问题

**改进**：审查效率提升、覆盖更全面

---

## 场景 4：新人入职

### 场景描述
新入职的研发工程师需要快速了解项目。

### 传统流程 (Before)
1. 阅读文档（往往过时）
2. 请教老员工（打断他人工作）
3. 通过代码摸索项目结构
4. 2-4 周后才能独立开发

**问题**：知识断层、上手慢

### DevSmart 流程 (After)
1. 新人在 DevSmart 中提问项目相关问题
2. **Supervisor** 从知识库中检索相关文档和历史讨论
3. 提供结构化的上下文（架构图、关键模块说明）
4. 推荐"入门任务"帮助熟悉代码

**改进**：知识可检索、上手周期缩短 50%
