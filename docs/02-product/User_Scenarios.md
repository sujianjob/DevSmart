# 用户场景

## 场景 1：新功能需求

PM 输入“支持团队成员邮箱邀请”。系统生成 PRD、澄清问题、任务列表和上下文包。

## 场景 2：需求不清

用户只输入“优化通知”。系统不直接产出任务，而是先追问通知类型、触发条件、目标用户和成功标准。

## 场景 3：技术负责人评审

TL 查看 PRD 后驳回，补充“必须支持邀请过期和重复邀请处理”。系统重新生成 PRD。

## 场景 4：研发接收任务

研发打开任务上下文包，看到 PRD 摘要、验收标准、技术约束、建议相关文件和测试场景。

## 场景 5：流程复盘

管理者查看事件时间线，确认卡点发生在 PRD 审批，而不是开发执行。
