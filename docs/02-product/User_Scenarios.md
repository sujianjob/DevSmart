# 用户场景

## 场景 1：新功能需求

产品经理输入“支持团队成员邮箱邀请”。系统识别目标用户、入口、邀请流程、过期规则和重复邀请等缺口，并生成澄清问题。

## 场景 2：需求不清

用户只输入“优化通知”。系统不直接生成 PRD，而是先追问通知类型、触发条件、目标用户、成功标准和不做范围。

## 场景 3：快速生成评审版 PRD

用户补充澄清答案后，系统生成 PRD 初稿，包含背景、目标、用户故事、主流程、边界、非目标和待确认项。

## 场景 4：生成 AC

系统基于 PRD 生成可测试的 AC，覆盖成功路径、失败路径、权限不足、重复提交、空状态等场景。

## 场景 5：评审前补漏

产品负责人查看待确认项和风险摘要，要求补充某个规则。系统根据反馈重新生成 PRD 和 AC。
