# 用户引导与上手流程 (Onboarding Process)

## 1. 团队接入流程

### 1.1 接入步骤

```mermaid
flowchart LR
    A[注册账号] --> B[创建团队]
    B --> C[邀请成员]
    C --> D[配置集成]
    D --> E[导入数据]
    E --> F[首次体验]
```

### 1.2 各步骤详情

| 步骤 | 操作 | 预计耗时 | 必需/可选 |
|:---|:---|:---|:---|
| **1. 注册账号** | 邮箱注册 / SSO 登录 | 1 分钟 | 必需 |
| **2. 创建团队** | 填写团队名称、规模 | 2 分钟 | 必需 |
| **3. 邀请成员** | 邮件邀请 / 链接分享 | 5 分钟 | 可选 |
| **4. 配置集成** | 连接 Jira/GitHub 等 | 10 分钟 | 推荐 |
| **5. 导入数据** | 导入现有任务/文档 | 15 分钟 | 可选 |
| **6. 首次体验** | 完成引导任务 | 10 分钟 | 推荐 |

## 2. 集成配置指南

### 2.1 项目管理工具集成

#### Jira 集成
```
1. 进入 设置 > 集成 > Jira
2. 输入 Jira 实例 URL
3. 创建 API Token (Jira 后台生成)
4. 授权访问权限
5. 选择同步的项目
```

**同步内容**：
- ✅ 任务状态双向同步
- ✅ 评论同步
- ❌ 附件不同步 (隐私考虑)

#### Linear 集成
```
1. 进入 设置 > 集成 > Linear
2. 点击 "使用 Linear 登录"
3. 授权团队访问
4. 选择同步的项目
```

### 2.2 代码仓库集成

#### GitHub 集成
```
1. 进入 设置 > 集成 > GitHub
2. 安装 DevSmart GitHub App
3. 选择授权的仓库
4. 配置 Webhook (自动)
```

**集成能力**：
- PR 事件监听
- Commit 变更追踪
- 代码上下文读取 (仅元数据，不上传代码内容)

## 3. 冷启动策略

### 3.1 无历史数据时的 AI 行为

| 场景 | 冷启动策略 |
|:---|:---|
| **PRD 生成** | 使用通用模板 + 行业最佳实践 |
| **上下文推荐** | 基于文件结构和命名推断 |
| **测试用例** | 基于 PRD 验收标准生成通用用例 |
| **告警分析** | 依赖日志关键词匹配 |

### 3.2 数据积累路径

```
第 1 周: 基础能力
    └── 使用通用模型，积累用户反馈
    
第 2-4 周: 初步学习
    └── 基于用户修改优化 PRD 模板
    └── 建立项目词汇表
    
第 1-3 月: 深度适配
    └── 代码库结构索引完成
    └── 历史 Bug 模式学习
    └── 团队偏好模型训练
```

### 3.3 快速建立上下文

| 操作 | 效果 | 优先级 |
|:---|:---|:---|
| **上传技术栈文档** | AI 理解技术约束 | P0 |
| **导入现有 PRD** | 学习写作风格 | P1 |
| **连接代码仓库** | 理解项目结构 | P0 |
| **标注核心模块** | 优先理解关键代码 | P2 |

## 4. 引导式首次体验

### 4.1 新用户引导流程

```
欢迎来到 DevSmart!
│
├── Step 1: 了解核心概念 (60s)
│   └── 动画演示：AI 如何辅助 PRD 生成
│
├── Step 2: 尝试生成第一个 PRD (3min)
│   └── 预设场景："帮我设计一个用户反馈功能"
│   └── AI 生成 PRD，用户体验审批流程
│
├── Step 3: 查看任务分发 (2min)
│   └── 展示 PRD 如何拆解为任务
│   └── 模拟任务分配通知
│
└── Step 4: 完成! 解锁全部功能
    └── 发放新人成就徽章
    └── 推荐下一步操作
```

### 4.2 功能发现提示

| 时机 | 提示内容 |
|:---|:---|
| 首次打开 PRD 编辑器 | "试试让 AI 帮你补充验收标准" |
| 首次查看任务列表 | "点击任务卡片查看 AI 注入的上下文" |
| 首次收到审批请求 | "您可以直接审批，或要求 AI 修改" |
| 使用 7 天后 | "解锁效能看板，查看团队数据" |
