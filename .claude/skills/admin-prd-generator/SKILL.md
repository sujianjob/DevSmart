# Admin PRD Generator - 产品需求文档生成工具

基于 `admin-reverse-docs` 输出的智能文档生成工具，**深度分析**前后端代码仓库的实现逻辑，生成完整的产品需求说明文档（PRD）。

**核心理念**：
- 不仅仅是接口映射，而是**深入代码实现**，理解业务逻辑
- **自动逐模块生成**，完成后统一输出审核清单，用户一次性确认

---

## 快速开始

### 1. 准备工作

```
✓ admin-reverse-docs 输出目录（包含 01_原始记录、02_数据模型 等）
✓ 前端代码仓库（Vue 项目）
✓ 后端代码仓库（Spring Boot 项目）
```

### 2. 提供必要信息

```
请提供以下信息：

1. admin-reverse-docs 输出目录路径：
   示例：./线索管理平台_admin_docs/

2. 前端代码仓库（本地路径或 Git 地址）

3. 后端代码仓库（本地路径或 Git 地址）
```

## 深度分析说明

### 分析内容

| 分析维度 | 具体内容 | 产出 |
|---------|---------|------|
| **业务校验** | if/else 条件、异常抛出 | 业务规则清单 |
| **状态流转** | 状态字段修改逻辑 | 状态机图 |
| **数据计算** | 金额计算、统计公式 | 计算规则说明 |
| **权限控制** | @PreAuthorize、手动检查 | 权限矩阵 |
| **事务边界** | @Transactional 范围 | 事务说明 |
| **事件驱动** | 事件发布和监听 | 事件清单 |
| **代码注释** | TODO、FIXME、业务说明 | 补充信息 |

### 业务规则识别模式

```java
// 模式1: 显式异常抛出 → 业务规则
if (条件) {
    throw new BusinessException("错误信息");
}

// 模式2: 状态检查 → 状态控制规则
if (entity.getStatus() != ExpectedStatus) {
    return error;
}

// 模式3: 自动填充 → 系统行为规则
entity.setCreateTime(LocalDateTime.now());
entity.setCreateBy(currentUser);
```
