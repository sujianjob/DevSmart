# DevSmart

DevSmart 是一个 AI 需求澄清与 PRD/AC 生成工作流工具。它帮助产品团队把一句模糊需求，转化为结构完整、边界清晰、可评审、可验收的需求包。

当前仓库处于**文档驱动设计与 POC 规划阶段**，目标是先验证最小闭环：用户输入一句需求后，系统能否在 10 分钟内产出可用于评审的 PRD、AC 和待确认项。

## 核心闭环

```text
模糊需求输入 -> 信息缺口识别 -> 澄清问题 -> 用户补充 -> PRD 生成 -> AC 生成 -> 边界补漏 -> 评审输出
```

## 产品边界

| 不做 | 做 |
|:---|:---|
| 代码生成 | 需求澄清 |
| 技术方案设计 | PRD 生成 |
| 接口或系统架构设计 | AC 验收标准生成 |
| 研发任务拆解 | 功能边界、异常场景和非目标补漏 |
| 外部工程工具调度 | 待确认项和评审摘要 |

## 30 天 POC

30 天版本只验证一个问题：DevSmart 能否把一句模糊需求转成产品经理愿意拿去评审的 PRD + AC。

交付物：

- 需求输入页
- 澄清问答页
- PRD 编辑与评审页
- AC 验收标准页
- 待确认项清单
- 需求包导出
- 评审记录

详细计划见 [30 天 POC 详细目标](docs/03-architecture/Thirty_Day_POC_Plan.md)。

## 本地开发

> 约束声明：仓库不启用自动 CI/CD；构建、测试、发布均为人工执行。

### 1. 手动启动后端

```bash
bash scripts/dev-backend.sh
```

### 2. 手动启动前端

```bash
bash scripts/dev-frontend.sh
```

### 3. 可选：写入演示数据

```bash
bash scripts/mock-demo.sh
```

该脚本用于写入本地演示数据，便于快速走通需求澄清到 PRD/AC 输出链路。

### 4. 演示路径

按照以下路径演示完整流程：

```text
输入需求 -> 回答澄清问题 -> 生成 PRD -> 生成 AC -> 查看待确认项 -> 完成评审
```

## 实施原则

- 产品范围：只做需求澄清、PRD、AC、边界补漏和评审输出。
- 模型：使用模型路由，不在业务逻辑中硬编码具体模型。
- 数据：优先保存用户输入、澄清记录、PRD、AC、待确认项和评审记录。
- 部署：POC 先轻量本地服务，生产阶段再评估更复杂部署。
- CI/CD：按仓库约束，不做自动触发。
